# 汎用発明エンジン 設計書（ドラフト v0.1）

作成：2026-11-09 ／ 状態：**v0.2 方針確定（12章）・1〜2週目の実装済み**（DNA v2・v1 からの変換、実験計画・ScenarioRunner）
対象期間：約11週（`docs/IMPLEMENTATION_STATUS.md` の現状を出発点とする）

## 0. この設計書の目的と範囲

**目標**：利用者が入力した「こんな道具がほしい」というイメージを、AIが**部品と機能ブロックの組み合わせ**で製品として設計し、
**組み立て式の実験**で検証し、**検証できない部分は理由とともに明示**できるようにする。

- 今の「雨具・空飛ぶ靴・運搬ロボットの3種類だけ」から、「機能ブロックで表せる発明なら何でも」へ広げる。
- 3つの既存デモは新しい仕組みの上で動く**サンプル兼回帰テスト**として残し、発表用デモを壊さない。

**やらないこと（安全と誠実さのための線引き）**

| やらないこと | 理由 |
|---|---|
| AIが書いたコード・数式・スクリプトの実行 | 安全に検証できない（CLAUDE.md の禁止事項）。AIの出力は**データとして検証してから**使う |
| 現実の性能・安全性の保証 | 簡易モデルの参考値。REALITY も「現実準拠の目安」 |
| 万能の物理シミュレーション（流体・熱伝導の精密計算など） | 卒業制作の期間・Quest の処理能力を超える。代わりに出典つきの簡易式を使う |
| 任意形状の3D生成を機能に使うこと | 見た目は機能に影響させない（外装のみ） |

> 仕様書 v2.0 では「未知の機構の自動生成」「あらゆる道具の3D生成」は FUTURE 扱い。本設計はその手前の
> 「**登録済みの機能ブロックの組み合わせ**による汎用化」であり、FUTURE そのものではない。指導教員の確認を推奨。

## 1. 全体像

```
利用者の入力（日本語）
   │
   ▼
[AI 設計]  ── 機能ブロックカタログ・部品カタログ・制約 を渡す（AIは一覧から選ぶだけ）
   │  出力：発明DNA v2 ＋ 機能対応表（どの要望をどのブロックで実現・検証するか／検証できない要望）
   ▼
[アプリで検証]  DnaJson v2（形式・範囲・参照・上限） → 不正なら拒否・理由表示
   │
   ▼
[組み立て]  部品（形・素材・取り付け位置）＋ 機能ブロック（試用時の動き）
   │
   ▼
[AI 実験計画]  ── 環境モジュール・シナリオ・計測項目のカタログを渡す
   │  出力：実験計画（データ）＋ 合格条件
   ▼
[アプリで検証]  ExperimentPlan 検証（モジュール・値の範囲・計測項目とブロックの組み合わせ）
   │
   ▼
[シナリオ実行]  人型モデルの行動 × 環境モジュール × 各機能ブロックのモデル → 計測
   │            DREAM（理想化）／ REALITY（質量・電力・出典つき係数）
   ▼
[結果]  計測値・合格判定・改良前後の比較・「検証できなかった要望」・現実化の課題
   │
   ▼
[改良]  言葉で依頼 → AIが update/add/remove 操作を提案 → 検証 → 承認 → 再実験
```

## 2. 発明DNA v2

v1（今の形式）はそのまま読めるようにし、読み込み時に v2 へ変換する。

```json
{
  "schemaVersion": 2,
  "id": "ai-night-light-bag",
  "name": "夜道を照らすリュック",
  "purpose": "暗い帰り道で足元を照らし、車に気づいてもらう",
  "tags": ["lighting", "safety"],
  "mount": "back",
  "appearance": "night_navy",
  "parts": [
    { "id": "pack", "type": "body", "shape": "box", "material": "fabric",
      "position": [0, 0, 0], "scale": [0.3, 0.42, 0.14] },
    { "id": "lamp", "type": "light", "shape": "cylinder", "material": "plastic",
      "position": [0, -0.18, 0.08], "scale": [0.05, 0.03, 0.05] },
    { "id": "cell", "type": "battery", "shape": "box", "material": "plastic",
      "position": [0, 0.1, -0.04], "scale": [0.07, 0.1, 0.03] }
  ],
  "behaviors": [
    { "type": "illuminate", "targetPart": "lamp", "parameters": { "lumens": 150, "beamAngleDeg": 60, "tiltDeg": 50 } },
    { "type": "alert", "targetPart": "lamp", "parameters": { "flashHz": 2, "visibleRangeM": 80 } },
    { "type": "power_supply", "targetPart": "cell", "parameters": { "capacityWh": 10 } }
  ],
  "functionMap": [
    { "need": "足元を照らす", "blocks": ["illuminate"], "status": "simulated" },
    { "need": "車に気づいてもらう", "blocks": ["alert"], "status": "simplified",
      "note": "見える距離を光の強さから概算。ドライバーの反応は扱わない" },
    { "need": "雨でも使える", "blocks": [], "status": "unverifiable", "note": "防水性能は検証できない" }
  ],
  "constraints": { "maxParts": 24, "maxSpeed": 3.0 },
  "revision": 1, "parentRevision": null
}
```

| 項目 | 変更点 |
|---|---|
| `category` → `tags` | 実験場と結び付けない。分類・ギャラリー表示用（固定の一覧から最大3つ） |
| `mount` | 取り付け位置：`head` `back` `waist` `wrist` `hand` `foot` `ground`（床を走る）`air`（飛ぶ）`fixed`（設置） |
| `parts[].shape` | `box` `cylinder` `sphere` `capsule` から選ぶ（Unity 標準の形。円錐・輪は専用メッシュが必要なため後回し） |
| `parts[].material` | `plastic` `aluminum` `steel` `fabric` `foam` `rubber` `glass`：密度で質量を計算（REALITY） |
| `functionMap` | 利用者の要望ごとに「どのブロックで実現・検証するか」「検証できるか」を記録。`status`：`simulated`（簡易モデルで検証）／`simplified`（大きく単純化して検証）／`unverifiable`（検証できない、理由つき） |
| `constraints.maxParts` | 12 → 24（形を細かく作れるように。Quest の描画負荷は実機で確認） |

**v1 → v2 の変換**：`category: protection` → `tags: ["protection"]`、`mount` は機能から推定（`follow_head`→`head`、`follow_user`→`ground`、`hover`→`air`）、`shape`/`material` は部品タイプの既定値。

## 4. 機能ブロック（24種、初版）

各ブロックは「パラメータ（範囲つき）」「簡易モデル（式と出典）」「出す計測値」「消費電力の式」「試用時の動き」を持つ。
**すべて C# 側のカタログに登録した決まったコード**で、AI は選ぶ・値を決めるだけ。

### 4.1 移動・追従（既存を拡張）
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `follow_user` 追従 | speed, followDistance | 追従・旋回速度制限（既存） | 追従誤差・到着の遅れ |
| `follow_head` 頭上追従 | heightOffset | 既存 | 位置ずれ |
| `navigate_to` 目標へ移動 | speed | 経路上の移動 | 所要時間 |
| `drive` 走行 | speedLimit, maxSlopeDeg | 坂の上り可否・転がり抵抗 | 坂の通過・電力 |
| `hover` 浮遊 | lift, maxHeight | 運動量理論（既存） | 高度・必要電力 |
| `propel` 推進（空中） | thrust, speedLimit | 既存（move_forward を改名） | 所要時間 |
| `stabilize` 姿勢安定 | stabilizationStrength | 揺れの減衰（既存） | 安定度 |
| `avoid_obstacle` 障害物回避 | detectionRange | 反応遅れつき回避（既存） | 衝突回数 |

### 4.2 保持・運搬
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `carry_load` 積載 | capacity | 積載量判定・加速の低下（既存） | 運べるか・電力 |
| `grip` つかむ | gripForceN, openingM | 摩擦係数 × 把持力 ≥ 重さ × 揺れの加速度 | 落とした回数 |
| `lift_load` 持ち上げ | maxLoadKg, liftHeightM, speed | 仕事率 P = m g v ÷ 効率 | 持ち上げ時間・電力 |
| `extend` 伸縮 | maxLengthM | 届く範囲の幾何判定 | 届いたか |

### 4.3 防護
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `rain_shield` 雨よけ | radius, effectiveness, skirtLength | 雨粒の衝突判定（既存） | 被濡れ・防護率 |
| `sun_shade` 日よけ | radius, opacity | 平行光線と身体円筒の影判定（雨と同じ方式） | 日陰率 |
| `impact_cushion` 衝撃吸収 | thicknessM, stiffness | ばね・ダンパーの落下モデル | 最大減速度（G） |
| `wind_block` 防風 | areaM2 | 抗力式で身体に当たる風荷重の低減 | 風荷重の低減率 |

### 4.4 環境の制御
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `illuminate` 照明 | lumens, beamAngleDeg, tiltDeg | 光度 I = lm ÷ (2π(1−cos(θ/2)))、照度 E = I cosα ÷ d² | 足元の照度（lx） |
| `heat` 加温 | powerW | 集中定数の熱モデル（熱容量・熱損失係数） | 温度上昇・到達時間 |
| `cool` 冷却 | powerW | 同上（ペルチェ素子の効率で割る） | 温度低下 |

### 4.5 検知・通知
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `detect` 検知 | rangeM, fovDeg | 視野角・距離・遮蔽の幾何判定 | 検知率・検知までの時間 |
| `alert` 通知 | loudnessDb / flashHz, visibleRangeM | 音：距離の逆二乗、光：見える距離の概算 | 届く距離 |

### 4.6 エネルギー・身体補助
| ブロック | パラメータ | モデル | 主な計測値 |
|---|---|---|---|
| `power_supply` 電源 | capacityWh | 全ブロックの消費電力の合計で割る | 稼働時間 |
| `solar_charge` 太陽光充電 | panelAreaM2 | 日射 × 面積 × 変換効率 | 発電量 |
| `assist_force` 動作補助 | assistN | 持ち上げ作業で利用者が出す力の低減 | 負担の低減率 |

> 係数（光の効率 lm/W、比熱、摩擦係数、素材の密度など）は `reality_model.json` と同じ形式（値・幅・確度・出典）で管理する。
> 初版は「推定・要調査」が多くなるため、**4〜6週目に出典調査**を入れる（雨具の係数と同じ手順）。

## 5. 組み立て式の実験

### 5.1 実験計画（ExperimentPlan）

```json
{
  "scenario": "walk_route",
  "durationSec": 20,
  "modules": [
    { "type": "darkness", "lux": 2 },
    { "type": "rain", "intensity": 10 },
    { "type": "obstacles", "count": 3 }
  ],
  "metrics": ["illuminance_at_feet", "alert_visible_range", "runtime", "mass"],
  "criteria": [
    { "metric": "illuminance_at_feet", "op": ">=", "value": 10, "reason": "足元の段差が見える目安（要出典）" }
  ],
  "seed": 2026
}
```

- AI が発明に合う計画を 1〜3 案出す。アプリが検証してから S04 に表示し、利用者は値を変えたり、モジュールを足したり外したりできる。
- **検証項目**：モジュールと計測項目が一覧にあるか、値が範囲内か、計測項目に必要なブロック・モジュールがそろっているか、合格条件の値が計測項目の範囲内か、数の上限（モジュール 6・計測 8・条件 4）。

### 5.2 シナリオ（人型モデルの行動）

| scenario | 内容 | 既存との対応 |
|---|---|---|
| `stand` | その場に立つ | RainLab |
| `walk_route` | 決まったルートを歩く | ObstacleCourse の案内役 |
| `carry_route` | 荷物を持って／運ばせて歩く | ObstacleCourse |
| `fly_to_target` | 目標地点まで飛ぶ（観察モード） | FlightDeck |
| `lift_task` | 荷物を持ち上げて置く | 新規 |
| `drop_test` | 発明品を落とす | 新規 |
| `sit_still` | 座って過ごす（加温・冷却向け） | 新規 |

### 5.3 環境モジュール

| type | パラメータ | 見た目 |
|---|---|---|
| `rain` | intensity mm/h | 既存の雨粒（計算と同じ軌跡） |
| `wind` | speed, direction | 風向きの矢印・揺れ |
| `obstacles` | count | 円柱（既存） |
| `slope` | angleDeg | 坂の床 |
| `temperature` | celsius | 温度計の表示・色味 |
| `sunlight` | elevationDeg, irradiance | 太陽の向き・影 |
| `darkness` | lux | 照明を落とす |
| `payload` | kg, sizeM | 箱 |
| `drop` | heightM | 落下台 |
| `targets` | count | 検知対象（人・物） |

### 5.4 計測項目（初版 22）

被濡れスコア、防護率、日陰率、衝突回数、追従誤差、到着の遅れ、所要時間、安定度、着地点のずれ、最大減速度（G）、
足元の照度、温度変化、到達時間、検知率、通知の届く距離、落とした回数、持ち上げ時間、負担の低減率、
消費エネルギー、稼働時間、総質量、装着部位の重さの上限判定。

各計測項目は「計算式」「必要なブロック・モジュール」「よい方向」「範囲」「単位」をカタログに持ち、`docs/experiments.md` に式を書く。

### 5.5 REALITY の共通層

- **質量**：部品の体積 × 素材密度 ＋ 電池。
- **電力**：各ブロックの消費電力の式の合計 → 稼働時間 = 電池容量 ÷ 電力。
- **成立性チェック**：推力 ≥ 重さ、坂の角度 ≤ 上れる角度、装着部位ごとの重さの目安（頭・手首・背中など、**出典を調べて設定**）。
- 既存の雨具（運動量理論・風荷重）・靴（人を浮かせる電力）・運搬ロボットの REALITY はこの共通層の具体例になる。

## 6. AI の役割と出力

| 呼び出し | 入力 | 出力（構造化出力・すべてアプリで検証） |
|---|---|---|
| 設計 | 依頼文、カタログ（部品・ブロック・形・素材・取り付け位置・外観） | DNA v2、機能対応表、設計の要点 |
| 実験計画 | DNA v2、実験カタログ | 実験計画 1〜3 案、それぞれの狙い |
| 改良 | DNA v2、直近の計測値、依頼文 | 操作リスト（update_parameter / add_part / remove_part / add_behavior / remove_behavior） |

- 依頼文に含まれる「ルールを変えて」などの指示は無視する（今と同じ）。
- `functionMap` の `unverifiable` が多い設計は、S02 でそのまま見せる（隠さない）。
- 費用：1 発明あたり設計＋実験計画で 2 回の呼び出し。プロキシでレート制限・1日の上限回数を設定する。

## 6.1 外装の3D生成（任意・既定はオフ）

- 「導線だけ引いて、使いたいときに使う」形にする（12章の決定）。
- アプリ：`IAppearanceGenerator`（外装を作る窓口）と、生成した外装を部品の外側に重ねて表示する仕組みを用意。既定は「生成しない」で、今の部品の見た目のまま動く。
- プロキシ：`/v1/appearance` を用意するが、`proxy/.env` に3D生成サービスのキーと名前を設定したときだけ有効。未設定なら「この機能はオフです」を返す。
- 安全：受け取るのは3Dモデルのデータだけ（GLB 形式・大きさ5MB以下・ポリゴン数の上限）。検証してから表示し、**見た目だけ**で判定・性能には使わない。
- 費用はサービスごとに異なるため、使うと決めたときにサービスを選ぶ。実装は7週目（見た目の週）。

## 8. 実装の構成

```
Core/
  Catalog/        PartCatalog, BlockCatalog, ExperimentCatalog（データ定義・範囲・式の説明）
  Dna/            DnaJson v2（検証）, DnaMigration（v1→v2）
  Blocks/         IBlockModel：Step(状態, 環境, dt) → 効果, PowerW, 計測への寄与（ブロックごとに1クラス）
  Experiment/     ExperimentPlan（検証）, ScenarioRunner（固定時間刻み・シード固定）, MetricCollectors
  Reality/        MassModel, PowerBudget, FeasibilityChecks, reality_model.json（係数の拡張）
Runtime/
  ScenarioPlayer（計算済みの軌跡と環境効果を再生）, EnvironmentVisuals, BlockVisuals（試用時の動き）
proxy/
  catalog.json（C# から書き出し、唯一の出典は C#）, prompts（設計・実験計画・改良）, schemas
```

- **既存コードの扱い**：RainSimulator・CourseSimulator は、それぞれ `rain` モジュールと `walk_route` / `fly_to_target` シナリオの中身として再利用する（計算結果が変わらないことをテストで確認）。
- **性能**：計算は実験開始時に一括で行い、再生だけを毎フレーム行う（今の方式）。部品数 24・粒子の上限を実機で計測して決める。

## 9. テストと評価

| 種類 | 内容 |
|---|---|
| 単体テスト | 各ブロックモデルの式（手計算との一致）、NaN・範囲外が出ない、計測項目の式 |
| 検証テスト | 不正な DNA v2・実験計画（範囲外・未知のモジュール・組み合わせ不正・上限超え）を必ず拒否 |
| 回帰テスト | 既存3デモの計測値が今と同じ（雨具の防護率、運搬の衝突回数、靴の安定度・必要電力） |
| 通し検証 | Editor 自動操作で、代表的な発明 6〜9 件を生成→実験→改良→保存（記録した AI 応答を使い、API は呼ばない） |
| **AI 評価セット** | 日常の困りごと 40 件の依頼で、①設計が検証を通る割合 ②実験計画が通る割合 ③機能対応表の「検証できない」割合 ④所要時間・費用 ⑤依頼との合致度（人が5段階で評価）を測る → 研究評価の数字にする |
| 実機 | 1〜2週ごとに fps・操作・読みやすさを確認 |

## 11. リスクと対策

| リスク | 対策 |
|---|---|
| 簡易モデルの信頼性への疑問 | 式と出典を画面と文書に明示、確度区分（標準値・文献値・推定・調整用）を全係数に付ける |

| AI の費用 | プロキシで回数制限・1日の上限、オフラインのサンプルでも全機能が試せるようにする |
| 既存デモの破損 | 回帰テストと通し検証を毎回実行 |
