# マネタイズ案（卒業発表用の構想）

作成：2026-11-16 ／ 状態：構想（未検証）。価格・料率・市場規模の数字は根拠がないため書かない。試行で確かめる仮説として扱う。

## 0. 最終目標

**誰でも想像を試作でき、それが製品の種として企業に届く場をつくる。**

利用者が VR で発明・実験・改良し、公開に同意した発明を、技術者・企業が見られる専用のページ（発明ライブラリ）に載せる。実現できると判断した企業・技術者が、商品として開発する。

## 1. 現実性の評価

「アイデアを公開すれば、誰かが拾って製品化してくれる」のままでは、成り立ちにくい。

| 課題 | 内容 |
|---|---|
| 前例がうまくいっていない | 一般の人の発明案を製品化する米国の Quirky は 2015 年に経営破綻した。自社で製造して在庫を抱え、1件あたりの開発費に対して売上が小さかった |
| 公開と特許の関係 | 公開すると新しさが失われ、特許が取りにくくなるのが原則（日本には公開から1年以内の新規性喪失の例外の手続きがある）。権利と対価の決まりが必要 |
| 技術者が参加する理由 | VR の試作品は基本形状の組み合わせなので、設計図としての価値は低い |

**成り立たせる方法**：価値の置き場所を「試作品の形」から「**需要の証拠**」に移す。このアプリは、次の3つを構造化されたデータ（発明DNA・実験結果・機能対応表）として記録している。

1. 誰が、どんな困りごとを持っているか
2. その人が試して、どこを直したか（改良の履歴）
3. 何を検証できて、何を検証できなかったか（機能対応表・REALITY の課題）

これに「**ほかの利用者が VR で試した人数と『欲しい』の数**」を加えると、いいねの数より強い需要の証拠になる。

成功している前例は、この型に近い。

- **LEGO Ideas**：一定の支持を集めた案を LEGO が審査して製品化し、採用案の発案者に売上の1%を払う（公表されている条件。発表前に最新の条件を確認する）。
- **企業の課題募集型**：企業がテーマを出し、外部から解決案を集める。

## 2. 段階的な計画

| 段階 | 内容 | 誰が払うか | 成功の目安（指標） |
|---|---|---|---|
| 0 今 | 卒業制作：VR で試作・実験・改良ができる | — | 下の「実績」 |
| 1 | 教育ワークショップ（発明の供給源） | 学校・科学館・自治体・企業の社会貢献部門・塾 | 実施回数・参加者数・また使いたい人の割合 |
| 2 | 企業の課題募集 | 企業（テーマごと） | 参加した企業の数 |
| 3 | **発明ライブラリ**（最終目標の柱） | 企業（月額の閲覧料） | 公開された発明の数・VR で試した回数 |
| 4 | **製品化の成功報酬**（最終目標の柱） | 製品化した企業（売上の一部） | 製品化された件数 |

**0 の実績（確認済みの事実のみ）**：Quest 3S の実機で 72fps で動作、AI の設計の評価で 38/38 件が検証を通過、雨具・運搬・移動の3種で試作から改良までを通しで確認。

**発表での伝え方**：目指す姿は3と4、最初の一歩は1。

## 3. 発明ライブラリ（段階3）

利用者が公開を許可した発明が並ぶ Web ページ。1件ごとに次を載せる。

- 困りごと（誰が、どんな場面で困っているか）
- VR の試作品の映像・3D 表示と、改良の履歴
- 実験の数値（改良前後）と、検証できたこと・できなかったこと
- ほかの利用者が VR で試した回数と「欲しい」の数（公開された発明を自分の VR に呼び出して試せる）

| 利用者 | 無料 | 有料（月額） |
|---|---|---|
| 個人のメイカー・学生 | 一覧・概要の閲覧 | — |
| メーカーの企画担当・スタートアップ・町工場 | — | 詳しいデータ、テーマごとの需要の傾向、発案者への連絡、データの書き出し |

**企業が払う理由**：市場調査・ユーザー調査の代わりになる。困りごとが実際にあり、試した人が欲しいと言ったという証拠が、自前で調べるより安く手に入る。

**収益の式**：月額料金 × 契約社数

## 4. 製品化の成功報酬（段階4）

1. 企業がライブラリで発明を見つける
2. 運営が間に入り、発案者とライセンス契約を結ぶ
3. 企業が設計・製造・販売する（**運営は製造しない**）
4. 売上の一部を発案者と運営で分ける

**収益の式**：製品の売上 × 料率（発案者と運営で分ける。比率は今後決める）

**小さい版**：個人の技術者がクラウドファンディング（Makuake など）で製品化する道を用意し、紹介料を受け取る。

## 5. 教育ワークショップ（段階1の詳細）

機材を持って学校や科学館に行く、90分の授業・イベント。

| 時間 | 内容 |
|---|---|
| 0〜10分 | 導入：困りごとをワークシートに書く |
| 10〜25分 | 班（4人）で1つ選び、「こんな道具がほしい」を文章にする |
| 25〜65分 | VR で発明・実験・改良（1人10分ずつ交代。残りはスクリーンを見て改良案を出す） |
| 65〜80分 | 発表（ギャラリーから呼び出し、改良前後の数値を見せる） |
| 80〜90分 | 振り返り：「検証できなかったこと＝現実にするための課題」を話し合う |

- 相手に渡すもの：当日の運営（スタッフ2人・機材一式）、班ごとの発明カード（印刷か PDF）、実施報告（参加人数・アンケートの集計）。
- 料金の形：基本料（機材・スタッフ・交通）＋参加人数。金額は無料の試行1〜2回のあとに決める。

**始める前にアプリに足りないもの**

| 必要なもの | 今の状態 |
|---|---|
| Quest 4〜6台の同時利用 | 未検証。今は PC 1台と Quest 1台を有線でつないで AI を使う。AI を使わないオフラインのサンプルなら台数に関係なく動く |
| スクリーンへの映写 | Quest の画面共有（キャスト）で対応できる見込み。未確認 |
| ワークショップ用の設定 | 未実装（体験の時間制限、班ごとのギャラリー、次の人向けのリセット） |
| 発明カードの書き出し | 未実装（保存データの JSON から作れる） |
| 安全・衛生 | 運用で対応（メーカーの対象年齢の確認、フェイスカバー、スタッフの見守り、イベント保険） |

## 6. 原価の目安

- AI の設計：評価の実績で、設計＋実験計画が1件あたり約 $0.05（評価セット40件で $2.07）。
- 生成外装：1回 約 $0.30（Tripo、利用者のメモ）。
- 1人の体験（設計3回・改良5回・外装1回）は数十円〜百円程度の見込み。改良1回あたりの料金はまだ集計していないので、発表前に評価ログから計算する。
- 原価のほとんどは、AI の料金より人件費と機材。

## 7. 想定される質問と答え

| 質問 | 答え |
|---|---|
| 素人の案は質が低いのでは？ | VR で試した人数と「欲しい」の数でふるい、最後は運営と企業が審査する（LEGO Ideas と同じ型） |
| 権利はどうなるの？ | 公開するときに「製品化されたら発案者に還元する」規約に同意してもらう。特許を取りたい人には、公開前に相談できる窓口を用意する |
| 失敗した Quirky と何が違う？ | Quirky は自社で製造して在庫を抱えた。こちらは製造しない。仲介とデータの提供に徹する |
| 最初は発明も企業も集まらないのでは？ | 先に教育ワークショップ（段階1）と企業の課題募集（段階2）で、発明の数と企業とのつながりを作る |
| 企業はなぜお金を払う？ | 需要の証拠（困りごと＋試用データ）が、自前の調査より安く手に入るから |

## 8. 将来必要になるもの（12週間の MVP には入れない）

- 公開時の同意と権利の決まり（発案者の名前の表示、利用許諾、公開前の特許相談の窓口）
- 未成年が作った発明の扱い（保護者の同意、匿名での公開）
- 不適切な投稿の審査
- 発明データの書き出し（設計図と実験結果はすでに JSON なので、ライブラリの土台にしやすい）
- AI プロキシのクラウド化（認証・回数制限・料金の上限）

## 10. 発表スライドの構成（約3分）

1. **ビジョン**（約40秒）：困りごとを持つ人と作る人の分断を、IMPOSSIBLE LAB がつなぐ。
2. **仕組み**（約50秒）：循環の図と、発明ライブラリの1ページの見本。VR で試した人数が需要の証拠になる。
3. **収益の仕組み**（約50秒）：③月額 × 契約社数、④売上 × 料率。運営は製造しない。
4. **道筋**（約40秒）：0 今 → 1 → 2 → 3 → 4。最初の一歩は試行ワークショップ。
