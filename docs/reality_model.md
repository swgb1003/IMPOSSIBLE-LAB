# REALITY MODE 簡易物理モデル（hover_canopy_v1）

更新：2026-11-04 ／ 対象：ハンズフリー雨具（頭上追従キャノピー）
係数データ：`Assets/_ImpossibleLab/Data/Reality/Resources/ImpossibleLabData/reality_model.json`
実装：`Assets/_ImpossibleLab/Scripts/Core/RealityModel.cs`（`ModeRules.Evaluate` から呼ばれる）

> このモデルは発表・教育用の **参考値** です。現実の製品としての性能・安全性は保証しません（仕様 1.2, 10章）。
> 雨の当たり判定（被濡れスコア・防護率）と DREAM MODE には影響しません。

## 1. 目的

従来の REALITY は「消費電力 = 25 + 90×面積 + …」のように根拠のない係数を使っていた（DECISIONS Q-02）。
これを **教科書的な物理式** と **出典・確度つきの仮定値** に置き換え、仮定の不確かさを **幅（悲観〜楽観）** で表示する。

## 2. 計算式

| 量 | 式 | 備考 |
|---|---|---|
| 総質量 m | 本体 + πr²×キャノピー面密度 + 2πr×L×側面カバー面密度 + 電池 | r：半径、L：側面カバー長 |
| 重さ W | m × g（g = 9.80665 m/s²） | 標準重力加速度 |
| 横から見た面積 A_side | 2r ×（キャノピー側面高さ比×r + L） | 浅いドーム＋側面カバーを長方形で近似 |
| 風荷重 F | ½ ρ C_d A_side v² | 抗力の基本式 |
| 必要推力 T | √(W² + F²) | 風に逆らって傾いた状態の釣り合い |
| 傾き θ | atan(F / W) | θ > 最大傾き なら「位置を保てない」 |
| 理想ホバー電力 P_ideal | T^1.5 / √(2 ρ A_rotor) | 運動量理論（アクチュエータ円板） |
| 消費電力 P | P_ideal ÷ (FM × 駆動効率) + 制御電力 | FM：性能指数 |
| 電池容量 E | 電池質量 × エネルギー密度 × 使用可能割合 | |
| 稼働時間 | E ÷ P | |
| 位置ずれ | F ÷ (K₀ ×（1 + k × 安定化の強さ）) | **調整用の仮定**（制御器に依存し物理的根拠なし） |

### 単純化と、その影響

- 風の中でホバリングすることは前進飛行に近く、実際は誘導電力が **下がる**。この効果を無視しているため、電力は **多めに**（保守側に）見積もっている。
- ロータとキャノピーの干渉、雨水の重さ、突風、地面効果、プロペラの騒音・安全性は扱っていない。
- 位置ずれは制御性能で大きく変わるため、物理式ではなく調整用の仮定値で表す。

## 3. 幅（悲観〜楽観）の出し方

各係数に `min` / `max` と `better`（大きいほど稼働時間が延びるか）を持たせている。

- **楽観**：すべての係数を、稼働時間が延びる側の端に置く
- **悲観**：すべての係数を、稼働時間が縮む側の端に置く
- **中央値**：`value`

すべての係数が同時に端の値を取るとは限らないため、幅は「最悪〜最良の組み合わせ」で、実際より広めに出る。
空気密度は電力を下げる側と風荷重を上げる側に同時に効くが、稼働時間の向き（`better: high`）にそろえている。

## 4. 確度の区分

| status | 画面表示 | 意味 |
|---|---|---|
| standard | 標準値 | 規格などで定まっている値 |
| literature | 文献値・要確認 | 文献にある一般的な値。具体的なページや形状への当てはめは未確認 |
| estimate | 推定・要調査 | 仮置きした値。根拠となる資料を探す必要がある |
| tuning | 調整用仮定（物理的根拠なし） | 見た目や挙動を整えるための値 |

現在の内訳（17件）：標準値 1、文献値・要確認 2、推定・要調査 11、調整用仮定 3。
係数ごとの値・幅・出典は JSON と、アプリ内の「実験環境設定 → REALITY → 前提係数と出典」に表示している。

## 5. 計算例（中央値、カッコ内は悲観〜楽観）

Python で同じ式を再計算し、Unity の表示と一致することを確認した（2026-11-04）。

| 設計・条件 | 総重量 | 風荷重 | 消費電力 | 稼働時間 | 位置ずれ |
|---|---|---|---|---|---|
| 半径0.6 m・カバーなし・安定0.3・風3 m/s（サンプル初期） | 2.06 kg | 0.8 N | 303 W（159〜588） | 10 分（4〜25） | 0.05 m |
| 同・風8 m/s | 2.06 kg | 5.6 N | 320 W（165〜631） | 9.5 分（3.7〜24） | 0.37 m |
| 半径0.8 m・カバー0.25 m・風4 m/s（自動検証の Rev.3） | 2.71 kg | 6.4 N | 470 W（239〜958） | 6.4 分（2.5〜16） | 0.42 m |
| 同・風8 m/s | 2.71 kg | 25.7 N | 734 W | 4.1 分 | 傾き44°で **位置を保てない** |

読み取れること（発表で使える）：

- 側面カバーは横からの雨を防ぐが、風を受ける「帆」になり、強風で位置を保てなくなる（防護と安定のトレードオフ）。
- 仮定の幅が 4〜25 分と大きく、実機の重量・推力の測定が必要だとわかる。

## 6. 今後の確認作業（要調査の解消）

1. FM・モータ/ESC効率：小型プロペラの試験データや論文で範囲を確かめる。
2. 本体質量・面密度：市販の小型ドローンと傘の公開仕様（重量・寸法）から概算し直す。
3. 電池エネルギー密度：出典（メーカー資料や総説）を特定する。
4. 抗力係数：Hoerner の該当ページを確認し、ドーム＋円筒の形状に合う値を選ぶ。
5. 市販ドローン1機種の公開仕様（重量・電池容量・飛行時間）でモデルを当てはめ、飛行時間が大きく外れないかを確認する。
6. 指導教員または工学系の方に、式と仮定の妥当性を見てもらう。

確認できたら JSON の `status` と `source` を更新する（コード変更は不要）。
